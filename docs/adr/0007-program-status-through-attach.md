# Answer OSC 7501 in the session and re-emit it to attachments from records

Status: accepted, 2026-10-10. Records the grilling of [#328](https://github.com/flotilla-org/cleat/issues/328); builds on the record store of [#326](https://github.com/flotilla-org/cleat/issues/326) and the Ghostty pin of [#327](https://github.com/flotilla-org/cleat/issues/327).

[OSC 7501](https://gist.github.com/mitchellh/7acae3abd8355c1c00287d67e96c913a) lets a program report what it is doing (`idle`, `working`, `done`, `blocked`, `error`) and lets the terminal keep one record per id. The specification says nothing about multiplexers, nested terminals or forwarding. Cleat sits between the program and every terminal that attaches to it, so it sets those rules here. libghostty-vt parses the reports and hands them to the embedder through `GHOSTTY_TERMINAL_OPT_PROGRAM_STATUS`; it keeps no records itself.

## Decision

1. **The session is the program's terminal.** The session's VT engine registers the program-status callback, and libghostty-vt answers `OSC 7501 ; ?` through the session's `write_pty`. Cleat writes no reply code of its own. The query is answered whether or not anything is attached, because Flotilla and Wheelhouse read the records directly. The program's query and reports never reach an attached terminal as raw bytes: any path that forwards the child's output strips OSC 7501, so an outer terminal cannot answer a second time.
2. **The session keeps the records.** It stores one record per id and applies the specification's lifetime rules. It drops `working`, `blocked` and `idle` on process exit and on OSC 133 A; the specification allows keeping `idle`, but cleat always drops it, so attachments and library consumers see the same records. It keeps `done` and `error` until acknowledged (rule 7), and removes every record on a full reset. Each record carries its source (`osc7501`, `title` or `recognizer`), so status inferred for programs that do not emit 7501 lives in the same store and vocabulary.
3. **Attach probes before it emits.** `cleat attach --program-status=auto|on|off` defaults to `auto`. In `auto`, attach sends `OSC 7501 ; ?` to the outer terminal at start-up and emits status only if the same reply arrives within a short timeout (about 200 ms, documented with the implementation). Attach consumes the reply. With no reply, status stays off for that attachment and is not re-probed. A reply that arrives after the timeout is still consumed and discarded for a bounded window (a few seconds, documented with the implementation), so it never reaches the session as stray input; it does not enable status late. `on` emits without probing, for passthrough setups that swallow replies; `off` never emits. The probe shares the start-up capability probing planned in [#58](https://github.com/flotilla-org/cleat/issues/58) and does not delay first paint beyond its timeout. A nested `cleat attach` needs no special case: the inner session answers the probe under rule 1.
4. **Attach re-emits records, not bytes.** On attach, attach sends one report for each current record. When a record changes, it sends the whole replacement report. When the session drops a record, it sends `state=clear` for that id. On detach, or when the session ends while attached, it clears every id it sent to that terminal, so a tab the user has left shows nothing stale. `done` and `error` records remain in the session and are replayed on the next attach.
5. **Ids pass through unchanged.** One attachment shows one session, and the outer terminal keeps records per tab or pane. Under nesting, each layer stores what the layer inside it re-emits and re-emits it unchanged in turn. No prefix is added.
6. **A program's own reports win over inferred status.** In what attach emits, a recognizer-derived record is used only until the program sends its first OSC 7501 report. After that, the program's own reports are authoritative until it exits. Exit means the same events that drop its `working` records under rule 2, process exit or OSC 133 A, so the next program starts without the flag. An inferred record uses the root id, as the program's own report would, so the outer terminal sees at most one live source per program. The store keeps both sources for consumers that do their own arbitration.
7. **Acknowledgement.** Typing into a live attachment acknowledges the session's `done` and `error` records. The session drops them, and every attachment and consumer receives `clear`. Focus alone does not acknowledge, because attach cannot reliably observe it. Library clients that do know focus (Wheelhouse) acknowledge through an explicit call. `cleat send` input does not acknowledge unless an opt-in flag (proposed `--ack`) says the script acts for a user.
8. **Which attachments emit.** Every live attachment whose probe succeeded receives the same re-emission, watchers included. History views receive none, because they show the past.

## Consequences

- Programs inside cleat report status even when the user's outer terminal cannot show it. Cleat's own consumers still benefit.
- Report text is decoded and free of control characters but remains untrusted. Anywhere it leaves the terminal (re-emission, `inspect`, Wheelhouse chrome), invisible formatting such as bidi overrides is removed, and the text is attributed to its session.
- Re-emitted sequences respect the specification's limits (4096-byte sequence, field sizes) because they are rebuilt from validated records.
- Tests need a nested cleat-in-cleat case under a 7501-capable outer terminal, asserting exactly one probe reply, and a silent outer terminal, asserting nothing is emitted.
- Deferred: letting a recognizer override a program's own reports, perhaps by a declared per-session preference. It will be decided when recognizers land ([#313](https://github.com/flotilla-org/cleat/issues/313)). The exact name of the `cleat send` acknowledgement flag is open.
