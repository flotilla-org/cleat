## Existing image path

[uishell_views.c](/Users/robert/dev/wheelhouse/src/uishell/uishell_views.c:3163) chooses in-process or daemon provider per terminal view. `session` attaches to an existing daemon session; `daemon:1` creates there. In-process provider requests `IMAGE_STATE` and `RENDER_UPDATES` (line 3179), and the session requests Ghostty (line 3206). During repaint, [lines 3718 onward](/Users/robert/dev/wheelhouse/src/uishell/uishell_views.c:3718) poll, obtain a render update, copy cells and images, mark observed, and release the update.

[Image-cache code](/Users/robert/dev/wheelhouse/src/uishell/uishell_terminal_glyph.c:5412) receives resource metadata keyed by image ID and generation. It calls `cleat_session_with_image_resource_data` synchronously, copies the borrowed bytes, decodes them and creates GPU textures. Unchanged valid generations reuse textures. Placements are copied before the render update is released, with provider-reported placement stride respected (line 5495). Missing bytes leave an invalid resource; later updates retry because only valid matching generations are skipped.

[Decoder](/Users/robert/dev/wheelhouse/src/uishell/uishell_terminal_glyph.c:5345) handles uncompressed RGB, RGBA, and PNG. Deflate and GRAY/GRAY_ALPHA are explicitly unsupported. Preserving encoded assets in cleat can remain compatible when the existing format/compression fields describe supported payloads; selecting new encodings would need decoder work or negotiated conversion.

[Placement drawing](/Users/robert/dev/wheelhouse/src/uishell/uishell_terminal_glyph.c:8854) has below-text and above-text planes, generation checking, source cropping, cell/pixel geometry, and proportional clipping to the terminal canvas. Kitty Unicode placeholders are suppressed as glyphs at [line 65](/Users/robert/dev/wheelhouse/src/uishell/uishell_terminal_glyph.c:65) so placements can draw them.

## Retention contract concerns

Wheelhouse caches textures because image resources currently derive from placements, with no exact image-store live set exposed. [The cache comment and implementation](/Users/robert/dev/wheelhouse/src/uishell/uishell_terminal_glyph.c:5424) record a prior streaming-producer memory problem and implement 320 MiB LRU eviction of resources not referenced by the current update (line 5557). Current references are exempt, so this is not a strict total memory ceiling. A retained-delivery design should distinguish asset existence, placement existence, and per-consumer residency. A disappearing placement alone cannot mean deleting the asset. Explicit release/invalidation or a recoverable resource lookup would allow clients to manage residency without guessing terminal retention.

The existing cleat [C callback](/Users/robert/dev/cleat/crates/cleat/src/provider_ffi.rs:2056) obtains bytes directly through the actor for in-process sessions; daemon sessions search `daemon.images` by ID and generation. [Render-update consumption](/Users/robert/dev/cleat/crates/cleat/src/provider_ffi.rs:2017) replaces `daemon.images` with pending packet images. [Packet receipt](/Users/robert/dev/cleat/crates/cleat/src/provider_daemon.rs:535) likewise replaces the pending image vector. Consequently, merely sending each asset once and then omitting it in later packets would not establish a persistent provider-side asset store. Wheelhouse's GPU cache masks some omissions until eviction/reconnect, but a cache miss needs a reliable fetch contract.

Current cleat [live packet construction](/Users/robert/dev/cleat/crates/cleat/src/packet.rs:210) supplies an empty image vector, while [history dispatch](/Users/robert/dev/cleat/crates/cleat/src/session.rs:3935) carries captured images. This explains why the same Wheelhouse callback can work in-process and on captured history yet fail for fresh daemon live images. Updating Wheelhouse's cleat pin alone cannot add bytes to those live packets.

Shared-attachment APIs are separate follow-up work: Wheelhouse currently offers watcher status and exclusive take-control in [uishell_views.c](/Users/robert/dev/wheelhouse/src/uishell/uishell_views.c:3252). It does not consume the newer fixed-size/state functions. Shared control semantics changed despite the additive ABI, so multiple attachments should be included in compatibility validation.
